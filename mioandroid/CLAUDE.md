# mioandroid

Android client for miolink, a personal single-user link manager. It talks to
`../miobackend` through the Connect RPC services defined in `../proto`, keeps
a local copy of the whole directory tree, and shows it with Jetpack Compose
and Material 3 Expressive.

Read `../miobackend/CLAUDE.md` for the domain model (directories, links, the
root directory) and the sync protocol. This file only covers the client side.

## Stack

| Concern | Library |
| --- | --- |
| UI | Jetpack Compose, Material 3 (`1.5.x`, for the Expressive components) |
| Navigation | Navigation 3 (`androidx.navigation3`) with `@Serializable` route keys |
| State | `ViewModel` + `StateFlow`, `lifecycle-runtime-compose` (`collectAsStateWithLifecycle`) |
| RPC | `connect-kotlin` on OkHttp, protobuf-javalite + protobuf-kotlin-lite |
| Local cache | Room (KSP) |
| Settings | DataStore; the API key is encrypted with Tink before it's stored |
| Images | Coil 3 (`coil-compose`, `coil-network-okhttp`), sharing the app's OkHttpClient |
| Opening links | Custom Tabs (`androidx.browser`) |
| DI | None. A manual `AppContainer` built in `MioLinkApplication` |
| Tests | JUnit 4, `kotlinx-coroutines-test`, Turbine, Robolectric (for in-memory Room on the JVM) |

Versions live only in `gradle/libs.versions.toml`. Material 3 is pinned there
on top of the Compose BOM because the BOM's version doesn't have the
Expressive components yet; drop the pin once the BOM catches up.

AGP has built-in Kotlin, so modules don't apply `org.jetbrains.kotlin.android`.
The root `build.gradle.kts` declares it with `apply false` only to choose the
Kotlin version. Keep `kotlin` in the catalog and the compose compiler plugin on
the same version.

## Modules

| Module | What it is |
| --- | --- |
| `:app` | The application |
| `:gen` | Protobuf and Connect code generated by buf from `../proto`. GENERATED, never edit. A plain Kotlin/JVM module |

`:gen` is committed, like `miobackend/gen`, so the app builds without buf.
Generated classes live under `dev.ikana.miolink.gen` (buf managed mode sets
`java_package_prefix`; protos never set language options).

## Layout

Packages under `app/src/main/java/dev/ikana/miolink/`, split by domain like the
backend, not by layer:

```
MioLinkApplication.kt    creates the AppContainer
AppContainer.kt          wiring only (the app's main.go): OkHttp, Connect client, Room, DataStore, repositories
MainActivity.kt          setContent { MioLinkTheme { MioLinkApp() } }; receives share intents
MioLinkApp.kt            back stack and NavDisplay; each screen owns its Scaffold and insets

core/
  network/               Connect ProtocolClient, API key interceptor, ConnectException -> app errors
  database/              Room database and migrations
  settings/              server base URL and API key storage
  ui/                    shared composables (ConfirmDeleteDialog, DirectoryPicker, ProgressButtonContent, ThumbnailImage, ...), openInCustomTab
navigation/              route keys and the back stack
ui/theme/                Color.kt, Type.kt, Shape.kt, Theme.kt (MaterialExpressiveTheme)

tree/                    the cached tree and the sync protocol
  TreeSource.kt          read side of the tree (flows, lastSyncError, refresh); faked in ViewModel tests
  TreeRepository.kt      implements TreeSource; applyWrite(), setLinkViews()
  TreeDao.kt, *Entity.kt Room entities and DAO for directories, links and the revision
  convert.kt             proto <-> entity
directory/
  DirectoryRepository.kt interface + DefaultDirectoryRepository: CreateDirectory, RenameDirectory, MoveDirectory, DeleteDirectory
  DirectoryName.kt       validateDirectoryName (the backend's rules, plus sibling duplicates)
  components/            DirectoryListItem, DirectoryActionsSheet, NewDirectoryDialog, RenameDirectoryDialog
link/
  LinkRepository.kt      interface + DefaultLinkRepository: CreateLink, UpdateLink, MoveLink, DeleteLink, RecordView, RefreshLinkMetadata
  LinkInput.kt           parseLinkUrl, validateLinkTitle (the backend's rules)
  LinkEditScreen.kt      opened after CreateLink so the user can fix the title
  LinkEditViewModel.kt
  components/            LinkCard, LinkActionsSheet, AddLinkSheet (+ clipboard helpers, input error messages)
browse/
  BrowseScreen.kt        a directory's contents: subdirectories and links, with their actions
  BrowseViewModel.kt
settings/                SettingsScreen, SettingsViewModel (base URL, API key, test with Ping)
```

Tests mirror the same packages under `app/src/test/`.

## Data flow and sync

Server state is handled by a local cache, not by fetching on every screen.
This is the Android counterpart of react-query, built on the backend's
revision protocol:

- **Room is the single source of truth for the UI.** DAOs return `Flow`s,
  ViewModels expose them as `StateFlow` with
  `stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000), ...)`, and
  screens collect them with `collectAsStateWithLifecycle()`. Screens never
  wait on an RPC to show data.
- **The cached revision is stored in Room** next to the tree, so the tree and
  its revision always change in the same transaction.
- **`TreeRepository.refresh()`** calls `GetTree(known_revision)`. On
  `not_modified` it does nothing; otherwise it replaces the whole tree and
  the revision in one transaction. It runs when the app comes to the
  foreground (`ProcessLifecycleOwner` `ON_START`), on pull-to-refresh, and
  after a write that found a different revision. Clients with no cache send 0.
  Concurrent calls share one request. It never throws: failures are logged,
  returned and exposed in `TreeRepository.lastSyncError`, and never clear
  the cache. `syncWhileStarted` (called from `MioLinkApplication`) also
  refreshes when the saved settings change.
- **The cache belongs to one server.** `SyncStateEntity.serverUrl` records
  where it came from; when the saved base URL differs, `refresh()` clears the
  cache before calling `GetTree`.
- **Writes** go through the domain repository: call the RPC, then
  `TreeRepository.applyWrite(previousRevision, revision) { /* local change */ }`.
  If `previousRevision` equals the cached revision, the local change and the
  new revision are written in one Room transaction. Otherwise the change is
  discarded and `refresh()` runs. The UI updates from Room either way.
  The lambda's receiver is `TreeDao`; use its in-place methods (`@Upsert`,
  `rename*`, `move*`, `delete*`), never a `REPLACE` insert, which SQLite runs
  as delete + insert and would cascade to the subtree.
- **Room mirrors the backend's cascades** (`ON DELETE CASCADE` on
  `parent_id` and `directory_id`), so a local recursive delete is one
  `deleteDirectory(id)`. The schema is exported to `app/schemas/` and
  committed; the database is excluded from backups since it's only a cache.
- **`RecordView` doesn't touch the revision.** Update `views` in Room
  directly after the call succeeds (`TreeRepository.setLinkViews`).
- No optimistic updates and no offline write queue for now. A write that
  fails shows an error and changes nothing locally.

## Rules

### Generated code
- Never hand-edit `gen/`. Change the `.proto` file and run `buf generate` from
  the repository root (or `make generate` in `../miobackend`), then follow
  `../proto/README.md`.

### Domains
- `directory` and `link` may import `tree` and `core`, but not each other.
  `browse` is the screen that combines them and may import `directory`,
  `link` and `tree`; nothing imports `browse`. `tree` imports only `core`.
  `core` imports no domain package, except `core/database/MioDatabase`,
  which Room needs to list every entity and DAO.
- Proto messages never leave the repositories. Convert them in the domain's
  `convert.kt` with `toEntity()` / `toProto()` style functions. ViewModels and
  composables see only entities or UI models.
- Timestamps from `google.protobuf.Timestamp` are stored in Room as `Long`
  unix milliseconds, UTC, like the backend.
- `AppContainer` is the only place that constructs dependencies. ViewModels
  get them through a `viewModelFactory { initializer { ... } }` that reads the
  container from the `Application`.
- ViewModels depend on interfaces (`SettingsRepository`, `LinkRepository`,
  `DirectoryRepository` with a `Default*` implementation; `TreeSource`, implemented by
  `TreeRepository`), so their tests use fakes.

### Network and errors
- Every request carries `Authorization: Bearer <api key>`, added by one OkHttp
  interceptor in `core/network`. Thumbnails (`GET /thumbnails/{name}`) are
  public; build their URL as base URL + `thumbnail_url`.
- Map `ConnectException` codes in `core/network`: `NOT_FOUND` means the cache
  is stale (refresh), `UNAUTHENTICATED` sends the user to settings,
  `ALREADY_EXISTS` and `INVALID_ARGUMENT` become messages shown next to the
  input, anything else is a generic error.
- Repositories call the backend through `ServiceClientsProvider.current()`
  (the clients for the saved settings, rebuilt when they change) on every
  call, never a client they kept, and unwrap responses with
  `getOrThrowApi()`, which throws `ApiException(ApiError)`. A transport
  failure (DNS, refused, TLS, timeout) is `ApiError.Unreachable`.
- Never log the API key, and never store it unencrypted. The settings
  DataStore and the Tink keyset are excluded from backups (`res/xml`): the
  Keystore key that wraps them never leaves the device, so a restored copy
  couldn't be decrypted. An undecryptable key reads as "not configured".
- Cleartext `http://` is allowed only in debug builds
  (`src/debug/res/xml/network_security_config.xml`).

### UI
- Wrap the app in `MioLinkTheme`, which uses `MaterialExpressiveTheme` with
  `MotionScheme.expressive()`, dynamic color on Android 12+ and the schemes in
  `Color.kt` otherwise. Define shapes in `Shape.kt` instead of hardcoding them
  in components.
- `ExperimentalMaterial3ExpressiveApi` is opted in once in
  `app/build.gradle.kts`, not per file. `ExperimentalMaterial3Api` (still
  needed for `ModalBottomSheet`) is opted in per composable that uses it.
- `core/ui` can't import `tree`, so `DirectoryPicker` takes
  `PickerDirectory` (id, parent, name); callers map their entities.
- Screens are split into a stateful `XxxScreen(viewModel)` and a stateless
  `XxxContent(state, onAction)` that previews and tests use.
- Deleting a directory always shows the confirm dialog first (deletes are
  recursive), with the subdirectories and links it removes counted from the
  cache (`TreeSource.subtreeCount`).
- Write dialogs (`BrowseUiState.dialog`) stay open while their RPC runs,
  with a `LoadingIndicator` in the confirm button and dismissal blocked.
  Names are validated before sending; `ALREADY_EXISTS`/`INVALID_ARGUMENT`
  show under the name field and unreachable/unknown failures in the dialog,
  so the user can retry. `NOT_FOUND` closes the dialog and refreshes;
  `UNAUTHENTICATED` closes it with a snackbar offering Settings. Success
  closes it with a snackbar.
- `Browse` adds things through a `FloatingActionButtonMenu` (New link, New
  directory) that hides while scrolling down; a long press on a
  subdirectory (rename, move, delete) or a link (edit, move, delete) opens
  its actions sheet, also exposed as accessibility custom actions. The root
  has no actions.
- `AddLinkSheet` is a form only: it takes the destination, an optional
  `initialUrl` and an optional `onDirectoryChange` (which adds a "Change"
  button opening `DirectoryPicker`), and reports `onSave(url)`; the caller
  runs `CreateLink`, passes `isSaving`/`failure`, and removes it on success.
  The URL is prefilled from the clipboard only when it holds an http(s)
  URL; on Android 12+ it's read only if the system already classified the
  clip as a URL (reading shows a toast), otherwise a paste button offers it.
  A created link opens `LinkEdit` (`BrowseUiState.editLinkId`).
- `LinkEdit` saves the title from the top bar only when it changed (trimmed,
  validated first), asks before discarding an edited title, and moves,
  refreshes metadata and deletes in place. It closes itself
  (`LinkEditUiState.exit`) after saving or deleting, or when the link
  disappears from the cache (deleted elsewhere); `onClose(message)` hands a
  message to the `Browse` entry below, which shows it in its snackbar.
- `Browse` shows the cache only. Sync errors are snackbars over cached data
  (`UNAUTHENTICATED` offers Settings); with nothing cached, a full-screen
  error with Retry or Settings. A directory deleted elsewhere navigates to
  its nearest existing ancestor (`BrowseUiState.redirectTo`).
- Links open in a Custom Tab, then `RecordView` counts the view.
- Thumbnails load through `core/ui/ThumbnailImage` (Coil `AsyncImage`).
  `AppContainer.imageLoader` uses the shared OkHttpClient and is installed as
  Coil's singleton by `MioLinkApplication` (`SingletonImageLoader.Factory`).
- Until server settings are saved, the app opens `Settings` alone, without
  a back arrow; saving swaps it for `Browse`.
- Sharing a URL to the app (`ACTION_SEND`, `text/plain`) calls `CreateLink` in
  the current or root directory and opens `LinkEditScreen`.

### Tests
- Test repositories and the sync logic with a fake Connect service and an
  in-memory Room database (`Room.inMemoryDatabaseBuilder` under Robolectric). Test ViewModels against fake repositories with
  `kotlinx-coroutines-test` and Turbine. No network; a local OkHttp
  `MockWebServer` is fine for the HTTP layer.
- Robolectric is configured in `app/src/test/resources/robolectric.properties`
  (SDK 36, a plain `Application` so tests don't build the real
  `AppContainer`). Android Keystore isn't available there; test with an
  in-memory Tink AEAD.

## Tasks

`tasks/NNN_<name>.md` files each describe one unit of work, sized for one
session, with the same rules as `../miobackend/tasks/`: each lists its
dependencies, starts with a `Status:` line set to `done` in the commit that
completes it, and updates this file if it changes a decision recorded here.
